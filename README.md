# ClipQueue — очередь и автопостинг видео в TikTok с Android

Kotlin, Jetpack Compose (Material 3), Room, WorkManager, DataStore, Coroutines/Flow, Photo Picker,
Media3, Coil, OkHttp. minSdk 26 (Android 8), targetSdk 35. Тёмная тема по умолчанию.

## 1. Что умеет TikTok официально и что из этого следует

| Способ | Что делает | Условия |
|---|---|---|
| Intent в приложение TikTok (описан в документации Share Kit) | Открывает видео в редакторе TikTok | Только установленный TikTok. Описание не передаётся — приложение копирует его в буфер. Кнопку «Опубликовать» нажимаете вы |
| Content Posting API, Upload (`video.upload`) | Загружает видео во «Входящие» TikTok | Своё приложение на developers.tiktok.com + Login Kit. Публикацию завершаете вы одним касанием |
| Content Posting API, Direct Post (`video.publish`) | Публикует полностью автоматически, возвращает статус и ID поста | То же + разрешение `video.publish`. **До аудита TikTok** посты только приватные, аккаунт должен быть приватным, не более 5 пользователей в сутки. Видимость пользователь выбирает сам, без значения по умолчанию. Перед каждым постом запрашивается `creator_info` |

Лимит описания в API — 2200 символов (UTF-16). Отдельного лимита на число хештегов в документации API нет,
но приложение TikTok сейчас предупреждает «Maximum 5 hashtags» — поэтому лимит в ClipQueue настраивается, по умолчанию 5.

## 2. Что работает и что требует от вас действий

Работает сразу, без ключей: очередь, выбор видео, миниатюры, просмотр, проверка файлов, замена видео,
копирование и массовое редактирование заданий, перетаскивание, поиск, фильтры, наборы хештегов,
шаблоны с категориями, режимы вставки хештегов, ручная правка описания, обязательная проверка текста,
расписание с интервалом, днями, окном и часовыми поясами, календарь, заблаговременная подготовка
и напоминания, точные будильники, восстановление после перезагрузки, история и статистика,
режим B (публикация с подтверждением через приложение TikTok), удаление всех данных.

Требует вашего TikTok Developer App и бэкенда: режим A (загрузка во «Входящие» и прямая публикация),
OAuth-вход, обновление и отзыв токенов.

Требует вашего нажатия всегда: режим B и режим «Входящие» — финальная кнопка в TikTok. ClipQueue
не имитирует нажатия, не использует Accessibility Service и скрытые API.

Статус «Опубликовано» ставится только по `PUBLISH_COMPLETE` от TikTok API или после вашего подтверждения.
Если автопубликация невозможна (нет входа, нет разрешения, не выбрана видимость, включена проверка текста,
режим B), задание переходит в «Требует подтверждения» с объяснением причины.

### Насколько автоматично

- **Режим A, прямая публикация (API)** — полностью без вашего участия: видео уходит в TikTok по расписанию
  и получает статус по ответу TikTok. Это единственный официальный способ публиковать без нажатий.
  Видимость выбирается для группы видео сразу (Видео → выбрать несколько → «Кто увидит»).
- **Режим B (без API)** — одно касание на видео: уведомление → TikTok с открытым видео, описание уже в буфере →
  «Вставить» и «Опубликовать». Подтверждение — кнопкой «Опубликовано» прямо в уведомлении.
- Имитация нажатий в TikTok (Accessibility Service) не используется: правила TikTok запрещают автоматическое
  взаимодействие с сервисом, это грозит блокировкой аккаунта и ломается при каждом обновлении TikTok.

## 3. Сборка APK

**Без компьютерных программ (GitHub Actions).** Загрузите содержимое папки проекта в новый репозиторий
на github.com (включая скрытую папку `.github`). Во вкладке Actions запустится сборка (5–10 минут),
скачайте артефакт `ClipQueue-apk`, внутри — `app-debug.apk`. Там же артефакт `test-report` с результатами тестов.

**Android Studio.** Откройте папку проекта, дождитесь синхронизации Gradle, затем
Build → Build App Bundle(s) / APK(s) → Build APK(s). Файл: `app/build/outputs/apk/debug/app-debug.apk`.

**Командная строка.** Один раз `gradle wrapper`, затем `./gradlew assembleDebug`.

Установка: перенесите APK на телефон и разрешите установку из неизвестных источников.

## 4. Тесты

- `./gradlew testDebugUnitTest` — JVM-тесты: наборы хештегов, нормализация и дубликаты, сборка описания
  (все режимы вставки, лимит, шаблоны по категориям, ручная правка), планирование и пересборка после
  перезапуска, ядро публикации на подменённых API (статусы, обязательная проверка, отсутствие входа,
  повторы временных ошибок, отсутствие повторной отправки, ошибки TikTok), проверка доступности видео.
- `./gradlew connectedAndroidTest` (нужен подключённый телефон или эмулятор) — Room: создание и изменение
  заданий, сохранение порядка очереди, атомарный переход статуса, наборы хештегов, история после удаления.

Отчёт: `app/build/reports/tests/`.

## 5. Настройка TikTok Developer App (для режима A)

1. Зарегистрируйтесь на https://developers.tiktok.com и создайте приложение (Manage apps → Connect an app).
2. Добавьте продукты **Login Kit** и **Content Posting API**. В Content Posting API включите
   **Direct Post**, если нужна прямая публикация.
3. Запросите scopes: `user.info.basic`, `video.upload`, `video.publish`.
4. Разверните бэкенд (раздел 6) и укажите в Login Kit Redirect URI: `https://<ваш-worker>.workers.dev/callback`.
5. Отправьте приложение на ревью TikTok. Пока Direct Post не прошёл аудит, посты будут приватными.
6. В ClipQueue: Настройки → способ публикации API → Client Key и адрес бэкенда → «Подключить TikTok».

## 6. Бэкенд (обязателен для API)

TikTok выдаёт токены только в обмен на `client_secret`, которого не должно быть в APK.
Минимальный бэкенд — `backend/worker.js` (Cloudflare Workers, бесплатный тариф):

```
cd backend
npx wrangler secret put TIKTOK_CLIENT_KEY
npx wrangler secret put TIKTOK_CLIENT_SECRET
npx wrangler deploy
```

Маршруты: `/callback` (возврат в приложение), `/token`, `/refresh`, `/revoke`. Секреты хранятся в
зашифрованных переменных Cloudflare. На телефоне токены шифруются ключом Android Keystore.

## 7. Расписание и ограничения Android

- Первое видео после запуска очереди уходит в ближайший разрешённый слот, следующие — с интервалом
  от предыдущей публикации, только в разрешённые дни и окно (окно может переходить через полночь).
  Видео с конкретным временем расписание не трогает; время задаётся в выбранном часовом поясе.
- За N минут до публикации задание готовится заранее: проверка файла, снимок описания, напоминание.
- По умолчанию WorkManager: задачи переживают перезагрузку, но в Doze возможна задержка на минуты.
  Точные будильники запускают публикацию в нужную минуту (Android 12+ попросит разрешение).
  Точность до секунды не гарантируется ни Android, ни TikTok.
- После перезагрузки, обновления приложения и смены времени расписание пересобирается (`BootReceiver`).
- Android 10+ запрещает открывать приложения из фона, поэтому режим B начинается с уведомления.
- Интервал не обходит лимиты TikTok: при дневном лимите задание останавливается с понятной ошибкой.

## 8. Безопасность

Пароль TikTok не запрашивается и не хранится. `client_secret` — только на бэкенде. Токены зашифрованы
(Keystore AES-GCM). Все запросы — HTTPS. Повторная отправка исключена атомарным переходом статуса,
а после загрузки видео в TikTok ролик не отправляется повторно ни при каких ошибках. Разрешения Android:
только уведомления, точные будильники (по желанию), автозапуск после перезагрузки, сеть, foreground-сервис
загрузки. Доступа ко всему хранилищу нет — только к выбранным видео. «Удалить все данные» отзывает
доступ TikTok, освобождает доступ к видео и очищает базу, настройки и кэш.

## 9. Архитектура

```
app/src/main/java/com/clipqueue/app/
  ClipQueueApp.kt           контейнер зависимостей, Coil, каналы уведомлений, восстановление заданий
  data/                     Room (задания, наборы, шаблоны, журнал, история публикаций), DataStore,
                            репозитории, QueueActions (операции пользователя), DataWiper
  domain/                   HashtagNormalizer, CaptionBuilder + TemplateResolver, ScheduleCalculator, QueuePlanner
  engine/                   PublishEngine — ядро публикации без зависимостей от Android,
                            Contracts.kt — интерфейсы (PostingApi, TokenProvider, QueueStore, Notifier, VideoAccess),
                            PostPreparer — проверка файла и сборка описания
  media/VideoInspector.kt   метаданные, постоянный доступ к URI, проверка доступности
  auth/                     OAuth Login Kit через Custom Tabs, Keystore, обновление и отзыв токенов
  publish/                  Content Posting API (creator_info, init, chunk upload, status), Intent в TikTok
  work/                     PublishWorker (фазы prepare/publish/status), PublishScheduler, будильники,
                            BootReceiver, уведомления
  ui/                       Главная, Видео, Расписание, Хештеги (+ Шаблоны), Настройки, История,
                            карточка задания, экран подтверждения
backend/worker.js           обмен кода OAuth на токены, обновление и отзыв (client_secret только здесь)
```
